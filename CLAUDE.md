# Explorables

A series of self-contained sites, one directory per episode. Episode 01 is
`deep-time/`. See README.md for what the format is and what makes a candidate
worth building.

The two rules below are not preferences. They are the reason this repo is a
series instead of a pile of sites, and they override any convention that
conflicts with them.

## Rule 1: Markdown is the source, Python builds the HTML

From episode 02 onward, page content is written as Markdown with custom
notation for sections, and the HTML is generated by a Python build in the
episode directory. Do not hand-write episode pages as HTML.

- Content lives in `<episode>/content/*.md`. The build writes the HTML.
- TOML frontmatter (`+++ ... +++`, read with stdlib `tomllib`) carries the
 numbers. Fenced directives (`::: name ... :::`, mistune 3) mark sections.
 Markdown carries the prose.
- Available already, do not add new dependencies for this: mistune, Jinja2,
 markdown-it-py, PyYAML, and `tomllib` in the standard library.
- `deep-time/` predates this rule and stays hand-written HTML. Do not port it.

**The mkdown hook is off for this repo.** `.no-mkdown` at the repo root turns
off the global PostToolUse hook that renders every edited `.md` to a sibling
`.html`. Markdown here is build input, not a document, so an auto-rendered
`.html` next to it would be noise at best and a clobbered file at worst. Leave
that file in place. The opt-out lives in `~/.agents/hooks/mkdown-render.py`.

## Rule 2: every episode is a COMPLETELY different website

This series exists for authenticity and creativity, so each episode must be
different from every other one. Not a new colour scheme on the same site: a
different design, structure and set of devices, chosen because that subject
demands them.

Deep Time was the apprentice project. Everything after it is the master project.

What this means in practice:

- Do not reuse an episode's look. Invert the axes deliberately: surface,
 typography, image register, index device, navigation, page schema.
- Do not reuse an episode's structural trick. If Deep Time made its argument
 with a proportional column and a vertical scroll, the next episode makes its
 argument some other way, even when a proportional column would work.
- `assets/` at the repo root holds only what has no look attached: behaviour
 (`lightbox.js`) and the favicon. A stylesheet or a typeface belongs to the
 episode that uses it, never to the repo. If something looks shareable,
 that is usually a sign two episodes are drifting toward each other.
- `tools/gen_img.py` is the one real exception. It is an engine, it knows
 nothing about any subject, and each episode supplies its own `prompts.py`.

When a decision would make two episodes resemble each other, take the other
option and say why in the commit.
